## Commands

```bash
# Start both frontend (Next.js) and backend (Convex) simultaneously
npm run dev

# Start only the Next.js frontend
npm run dev:frontend

# Start only the Convex backend
npm run dev:backend

# Build for production
npm run build

# Lint (excludes convex/_generated/)
npm run lint
```

The `predev` script runs before `dev`: it waits for Convex to be ready, runs one-time setup (`setup.mjs`), and opens the Convex dashboard. On first run you'll need to complete Convex auth setup.

## Required Environment Variables

Set via `npx convex env set <KEY> <VALUE>`:
- `GOOGLE_API_KEY` — Google Generative AI (embeddings + Gemini models)
- `CONVEX_SITE_URL` — Used by Convex Auth config

## Architecture

This is a **Next.js 16 + Convex** full-stack app. Convex is both the database and backend runtime.

### Key architectural layers

**Frontend** (`app/`, `components/`):
- `app/quiz/page.tsx` → renders `QuizGenerator` component for topic-based quiz generation
- `app/server/` → SSR demo using preloaded Convex queries
- `components/QuizGenerator.tsx` — calls `api.questionGenerator.generateQuizQuestions` via `useAction`

**Convex backend** (`convex/`): All backend logic. The `_generated/` directory is auto-generated by the Convex CLI — never edit those files.

### Two quiz generation pipelines

1. **Topic-based** (`convex/questionGenerator.ts`): LangGraph multi-agent workflow. Uses a supervisor pattern: `supervisor → TopicGenerator → supervisor → QuestionGenerator → FINISH`. Generates 3–5 subtopics then 10 questions per subtopic in parallel. Uses `gemini-2.0-flash`. Must use `"use node"` directive since LangGraph requires Node.js APIs.

2. **Document-based** (`convex/fileQuestionGenerator.ts`): Sequential LangGraph pipeline: `enhance → retrieve → generateSubtopics → generateQuestions`. Enhances the user query, retrieves relevant document chunks via vector search, then generates questions grounded in document content. Also requires `"use node"`.

### RAG system (`convex/ragActions.ts`, `convex/documents.ts`)

- Documents are split into 1000-char chunks with 200-char overlap, embedded using `gemini-embedding-001` (3072 dimensions), and stored in the `documents` table with a vector index.
- `documents.vectorSearch` is a Convex `action` (not a query) because it calls the external Google API for query embedding before invoking `ctx.vectorSearch`.
- `documents.fetchResults` is an `internalQuery` — used only by other Convex functions, not directly from the frontend.
- `ragActions.ragChat` performs full RAG: embed query → vector search → fetch chunks → generate answer with `gemini-2.5-flash`.

### Convex function types

Convex has three function types with distinct constraints:
- **`query`**: Read-only, reactive, can be preloaded for SSR
- **`mutation`**: Writes to DB, transactional
- **`action`**: Can call external APIs and other Convex functions; not transactional. Required for anything using Google AI SDK. Add `"use node"` at the top of the file if the action uses Node.js-only packages (e.g., LangGraph).

### Schema

The `documents` table has a vector index `by_embedding` (3072 dimensions) and two regular indexes: `by_fileName` and `by_source`. Auth tables are provided by `@convex-dev/auth`.

### Auth

Uses `@convex-dev/auth` with a built-in Convex provider (not an external OAuth provider). The `ConvexClientProvider` wraps the app and handles session management.
